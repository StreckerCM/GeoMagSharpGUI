Notes on Mockup 3 — Toggle uncertainty rows above

  • Each date produces 2 rows: the value and its ±1σ uncertainty (yellow tint).
  • Coverage flag and model category live in a status strip at the bottom — finds a home outside the grid.
  • Toggle hides uncertainty rows when you want a tight scrollable view (e.g. for 30-day ranges).
  • Single grid means existing copy/export code works unchanged (every row is a date or a label).
  • Information dense, but with 5 dates this is already 12 rows; for 30 dates → 60+ rows with uncertainty on, ~30 with off.

Pattern C trade-offs: explicit and discoverable — the menu name tells you which gives you the slim version vs the firehose. Good for users who occasionally want a quick "what's on screen" CSV. Trade-off: two code paths and two menu items to maintain; users can be surprised when "Save Results" doesn't include uncertainty.

Comparing the three patterns

  • Pattern A — clearest UX, zero ambiguity, but no escape hatch for "smaller please." Recommended default.
  • Pattern B — flexible but adds a custom dialog. Worth it if users actually report wanting smaller files; otherwise yagni.
  • Pattern C — preserves "Save Results" muscle memory while introducing "Export Full Data" as a separate, deliberate action. Risk: surprise when grid view changes what gets saved.

Note for all three: JSON keeps schema cleanest (HDGM-only fields stay nested under uncertainty; missing values are null). CSV-wide is fine for ≤10 columns; once HDGM adds 7 σ values + coverage + components, it becomes 25+ columns and the long/tidy CSV format is more spreadsheet-friendly.
